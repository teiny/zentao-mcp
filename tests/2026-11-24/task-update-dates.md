# 任务部分更新字段保留验证

日期：2026-11-24。

## 执行前计划

范围：修复禅道17.0任务更新导致实际日期或完成者变化的问题。通过正式任务编辑流程读取并携带原业务字段保存，再回读任务；明确更正实际开始时间或完成者时，只改变指定字段，不发起完成、状态流转或计时。

环境：本机Node.js24；单元替身及stdio MCP连接本机HTTP模拟禅道，全部为合成数据。真实业务验证仅使用用户授权的对象与操作，业务描述、对象编号及数据快照不写入本仓库。

验证步骤与预期：

1. 新回归用例先在原实现复现描述更新导致实际开始时间清空。
2. 对未开始、进行中和已完成任务，仅改描述时保留原日期、完成者、状态、指派及工时。
3. 明确恢复实际开始时间或完成者时，仅相应字段改变，不重复完成或计时。
4. 非法日期、未知字段在请求前拒绝；缺少原字段、日期格式不明、多人或父子任务不写入。
5. 原生编辑读取、提交或回读失败均不自动重试。
6. stdio MCP完整链路模拟17.0任务API日期兼容性及已完成任务默认完成者行为，验证正式编辑流程的字段保留。
7. 执行全部测试、修改文件语法及diff格式检查；临时测试与业务MCP客户端退出并核实模拟端口释放。

- 原实现新增日期保留回归5项，4项失败，已复现进行中任务的实际开始时间变为零日期。
- 最终实现共135项单元及stdio MCP集成测试全部通过，失败、跳过、取消均为0；覆盖三种任务状态、日期和完成者明确更正、其他字段保留、非法输入及失败不重试。
- 命令：使用应用依赖提供的Node.js24执行 `node --test tests/*.test.js`；修改的src/index.js、src/write-tools.js及三个测试文件分别执行 `node --check`。
- `git diff --check`通过。没有编译脚本或依赖变更；未执行提交、推送或部署。
- 真实17.0实例通过新加载的stdio MCP验证日期恢复和完成者恢复，独立回读确认原值及其他业务字段；随后完成获授权的详情维护，并对全部范围逐条回读正文、附件及原业务字段。真实验证未发起完成或计时，也未调用业务直接REST。

- 当前常驻连接可能缓存旧工具实现；本次全部后续写入均使用启动于修复后的独立客户端，未回到旧写入连接。
